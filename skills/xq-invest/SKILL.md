# 技术评估

生成一份技术评估报告。核心只问一个问题：这个技术/框架是在创造新的系统秩序，还是在搬运旧方案？

## 认知起点

技术不是功能列表，是被问题照亮的秩序。技术选型就是拿手里的秩序去换一台更好的秩序生成器。

所以不列特性，看本质：
- 不问"这个功能有没有"，问"这个机制转不转得起来"
- 不问"社区多火"，问"社区在用什么过时的眼睛看它"
- 不问"能不能用"，问"我拿什么换什么，换完之后我的系统更聪明还是更笨"

## 输入

技术名称、官方文档、架构介绍、benchmark 数据、源码走读笔记，或任何描述该技术的材料。知名技术只给名字即可——用 Research skill 或 subagent 抓取最新版本、生态数据和社区反馈。

## 报告结构

以下五个区块是骨架，不是填空题。对某个技术来说哪个区块最有料，那个区块就多写；没料的一两句带过或直接跳过。报告为判断服务，不为完整性服务。

### 一、这是什么

一张技术定位表 + 一句自定义生态位定义。

| 维度     | 内容                                         |
|----------|----------------------------------------------|
| 技术名称 |                                              |
| 生态位定义 | 用我们自己的语言，不用市场标签（如"分布式 KV 存储"是隔的，"把一致性成本从写入转移到读取的基础设施"是不隔的） |
| 成熟度   | 实验性 / 早期采用 / 生产就绪 / 基础设施级     |
| 核心依赖 | 运行/部署必须依赖什么（内核版本、硬件特性、其他生态） |
| 数据快照 | 关键 benchmark / 性能数据 / 社区规模          |

生态位定义要穿透表面标签。"搜索引擎公司"是隔的，"人类认知基础设施的垄断运营商"是不隔的——后者告诉你它真正在做什么。

### 二、秩序创造机器判定

这是整份报告的心脏。不逐项打分，而是回答一个问题：**这台机器转不转得起来？**

从三个角度看：

**飞轮在不在转？**
系统有没有越用越好的结构——用的人越多场景越多，场景越多打磨越狠，打磨越狠用的人越多？这个循环是已经在转、刚开始、还是停着？转了多久？加速还是匀速？如果不转，什么卡住了？

**冲击后变强还是变弱？**
负载来了、硬件变了、需求变了——这个技术是碎掉、扛住、还是吃掉冲击变成自己的燃料？有没有真实案例？结果如何？

**资源是被推过来的，还是自己来的？**
推广靠的是一个一个团队去说服（推），还是别人主动涌过来因为不用就亏（引力）？有没有"不推而聚"的迹象？

**综合判定**：
- 秩序创造机器 — 飞轮在转，冲击后变强，资源自己来
- 有潜力 — 飞轮有结构但还没验证转起来
- 秩序搬运 — 把已有的东西重新排列，没有生成新秩序

### 三、创生公式

每台秩序创造机器都有一个核心机制。用一句话写出来。

参考：
- Linux = 所有人都能看到源码→所有人都能修→修的人越多越稳定→用的人越多
- eBPF = 内核事件→用户态程序→动态注入→不需要改内核就能扩展内核
- Transformer = 任意位置都能互相看见→并行计算→规模本身就是能力

然后回答：
- 这个公式被验证过几次？验证到什么程度？
- 别人在跑相似的公式吗？差异在哪？

### 四、社区看见的 vs 我们看见的

这一节决定采用时机。

**它在技术成熟度曲线的哪里？**
积累期、拐点、加速期、平台期。如果在拐点前——什么条件能触发拐点？

**社区在用什么旧眼睛看它？**
社区给它贴的标签是什么？这个标签遮住了什么？我们的框架看到了什么社区看不到的？认知差有多大——这是技术红利期的来源。

三个信号检测认知折价：
- 需要很复杂的解释别人才能听懂它的真正价值？
- 性能 benchmark 和实际场景存在系统性偏差？
- 已有的类比全部失效（"像 X 但又不像 X"）？

**它控制了什么别人拿不走的东西？**
权力来源是什么——数据格式、协议标准、生态锁定、人才聚集？这种控制是静态的（文档、API 稳定）还是动态的（越变越强）？
这个稀缺性未来会不会位移？技术有没有能力跟着位移走？

**它在搭哪趟便车？**
三种成本正在坍缩——理解成本、协作成本、部署成本。这个技术骑在哪一种上？坍缩释放的能量被它捕获了多少？

### 五、换不换

**采用建议**：建议投入 / 建议观察 / 建议放弃

**如果投入**：建议切入场景、关键验证实验、回滚策略

**核心假设**：这个决策依赖哪几个假设？每个假设附退出信号——什么数据出现说明假设错了，该停。

**未解问题**：3-5 个对决策至关重要但还没答案的问题，按优先级排。

### 最后一句

用一句话回答：这个技术的本质是什么？创造新秩序，还是搬运旧秩序？

- 用 Write 工具写入，写完告知完整路径

## 生成规则

1. 基于真实信息，不编造。信息不足的直接标注，不硬撑
2. 敢判断。"既可能好也可能坏"是废话，不许出现
3. 每个判断附证据——benchmark 数据、源码引用、具体场景
4. 禁止出现：社区很火、设计优雅、前景广阔、下一代技术
5. 以说透为准，不计字数。两千字能说清就两千字，需要七千字就七千字
6. 中文撰写
